## Compatibility, engineering choices and self-review

No dependency additions, generated-schema edits, SQLite DDL changes or compiler version changes.
The abort uses the existing versioned SecuritySignalPayload with a fixed redacted code and causal
dispatch reference. No raw arguments, resource text, credential, message body or key enters it.
`evidence.dispatch` centralizes the conservative count interpretation. Evaluation validates abort
causality; replay rejects it explicitly before substitution. Older consumers must not treat these
compensated traces as execution proof; all historical admissions already had an entry-uncertainty
window. See `docs/evidence-model.md` for the complete semantic contract.

A deliberate second pass examined receipt cleanup, terminal ordering, false call counts, trust
route pinning, event consumers, authority freshness and abort contradictions. It added the
post-evidence expiry check and effect-before-abort rejection. This was **in-session self-review**,
not fresh independent review. Python collaborators remain operator-owned; malicious code sharing
those object references is outside the sandbox guarantee.

Boundedness checks exercise a full 10,000-row audit fixture and 10,000 retained IDs. No production
latency, 100k-row, multi-writer throughput, power-loss, Windows or SLO claim is made. The global cap
is intentionally an availability limitation. Identity caps bound retained bookkeeping, not SDK
transport decoding or evidence-file size. Approval waits retain configured timeout; already entered
arbitrary dispatches can delay terminal completion until the caller settles/cancels them.
